# JobLens 추가 채용공고 공급원 조사

조사일: 2026-09-19. 대상은 개인 개발자가 국내 **여러 직종의 현재 공고**를 추천할 때 사용할 수 있는, Jooble·잡아바·잡알리오·고용24 직접 API 이외의 공식 데이터 공급원이다. 서울시는 사용자 발급 키로 연결을 검증했고, 그 밖의 국내 후보는 공개 신청 절차만 조사했으므로 실제 개인 계정 승인이나 정상 응답을 뜻하지 않는다. 공고 페이지를 무단 스크래핑하는 방식은 후보에 넣지 않았다.

## 우선순위와 판정

| 우선순위 | 공식 공급원 | 범위·접근·허락 | 미검증 사항 |
| --- | --- | --- | --- |
| 1 | [서울시 일자리포털 채용정보, OA-23047](https://data.seoul.go.kr/dataList/OA-23047/S/1/datasetView.do) | 2026-08-21 공개된 **새 데이터셋**. 서울·경기·인천의 고용24 기반 여러 직종을 매일 1회 갱신한다고 명시한다. 2026-09-19 `recMntList` 샘플 5건 및 사용자 발급 키 6건 호출이 정상 응답했다. 제목·본문·직종·마감일 등이 반환된다. | 응답에 공고 원문 URL과 고유 ID가 없다. 페이지는 자유이용이라 표시하지만 공식 카탈로그 API는 `자유이용 불가`로 반환해 재게시 권한이 불명확하다. 공식 호출 주소는 HTTP다. |

서울시의 [공공누리 0유형](https://www.kogl.or.kr/info/license.do)은 해당 공공저작물에 대해 출처표시 의무 없이 상업·비상업 이용과 변형을 허용한다. 그러나 이 데이터셋의 화면 표기와 공식 카탈로그 API의 이용허락 값이 충돌한다. **재게시·AI 요약·상용 운영을 허용받았다고 단정하지 않는다.** 또한 서울시 데이터셋의 허락이 고용24나 원 채용기업 사이트에서 *별도로 수집한* 전문·첨부파일에 자동 적용되는 것은 아니다. 이는 법률 확답이 아니라 확인 전까지의 제품 설계상 보수적 경계다.

## 서울시 데이터셋에서 확인할 세부 사항

- 구 [서울시 일자리포털 채용 정보 OA-13341](https://data.seoul.go.kr/dataList/OA-13341/A/1/datasetView.do)는 종료 안내가 보인다. 이름이 비슷한 **신규 OA-23047**을 대상으로 키와 명세를 받아야 한다. 신규 페이지는 2026-09-16 갱신, 매일 1회 주기, 서울·경기·인천 범위를 표시한다. 이는 **메타데이터의 갱신** 증거이지 최신 공고가 실제로 몇 건 들어 있는지의 증거는 아니다. [신규 데이터셋](https://data.seoul.go.kr/dataList/OA-23047/S/1/datasetView.do)
- 서울시의 [공통 API 안내](https://data.seoul.go.kr/together/notice/faqList.do?bbsCd=10002&ditcCd=FAQ02&seq=d47bc57aea53d6c6ab244c05a6eb2259)에 따르면 `sample` 키로 처음 5건을 조회할 수 있다. OA-23047 공식 Open API 탭의 서비스명은 `recMntList`로 확인했고 무키 샘플 요청을 재현했다. 세부 필드·제약은 [검증 문서](seoul-job-api.md)에 기록했다.
- 2026-09-19 공식 상세 화면의 서비스명 `recMntList`로 [샘플 호출](http://openapi.seoul.go.kr:8088/sample/json/recMntList/1/5/)과 사용자 발급 키 호출(6건)이 `INFO-000`으로 성공했다. 해당 시점 응답의 `list_total_count`는 42,758이다. 이는 **현재 모집 중인 공고 수가 아니다**. 검증 스크립트는 [여기](../../scripts/probe-job-sources.mjs)에 있으며 키를 저장하지 않는다.
- 반환 필드 38개에 `JOB_CONT`(본문), `JOBS_NM`(직종), `CLOSE_DT`(마감일) 등이 있으나 **원문 URL과 고유 공고 ID는 없다**. 추측한 URL을 만들거나 서울시/고용24 사이트를 크롤링하지 않는다.
- 공식 호출 주소는 `http://openapi.seoul.go.kr:8088`이고 HTTPS 8088 시도는 TLS 오류로 실패했다. 키를 브라우저에 노출하지 않고, 실제 운영 전 HTTPS 지원 경로나 공식 프록시 제공 여부를 서울시에 확인해야 한다.

## 채택 전 최소 검증

1. 서울시 OA-23047은 키와 첫 6건의 필드까지 확인했다. 다음은 서울·경기·인천 각 지역과 서로 다른 직종에서 현재 모집 중인 공고가 실제로 나오는지, 마감일·중복·정렬을 표본 조사한다. 원문 링크와 고유 ID가 없으므로 제공 가능 여부를 문의한다.
2. 공공데이터포털에서 장애인고용공단·사회복지시설 서비스의 개인 개발 키 신청 가능 여부를 확인하고, 각각 1~2회만 호출해 응답·마감·상세 링크를 검증한다. 공공데이터포털의 `자동승인` 표기만으로 키가 이미 발급됐다고 간주하지 않는다.
3. 데이터셋마다 **라이선스, 허용 필드, 캐시 기간, AI 요약, 재게시, 공개 운영 승인**을 별도로 기록한다. 데이터셋 메타데이터가 `수시` 또는 `실시간`이어도 응답에 끝난 공고가 섞이는지 확인해 최종 화면에서는 마감일과 원문 상태를 함께 검증한다.

결론: **Jooble + 서울시 OA-23047**은 여러 직종의 후보군을 넓힐 수 있지만 서울시 데이터는 아직 *연결성 검증* 상태다. 원문 링크·고유 ID 부재, 이용허락 표기 충돌, HTTP 키 전송 문제를 해결하기 전에는 사용자용 공고 추천 화면에 자동 게재하지 않는다. 장애인고용공단과 사회복지시설 API는 다른 사용자군·직종을 보완할 후보이며 아직 실제 응답을 확인하지 않았다.

## 키 없이 연결 확인한 해외 원격 공고 피드

2026-09-19에 [연결 점검 스크립트](../../scripts/probe-job-sources.mjs)를 1회 실행해 공식 피드의 응답을 확인했다. 이는 **연결·응답 형식 점검**이며 JobLens 화면에 공고를 게시하거나 한국 근무 가능성을 최종 판정한 것은 아니다.

| 공급원 | 실제 응답 | 한국 사용자에게 적용할 제한 |
| --- | --- | --- |
| [Himalayas](https://himalayas.app/docs/remote-jobs-api) | `country=KR` 검색 HTTP 200, 첫 페이지 20건, 응답의 `totalCount=2439`. | 국가 필터는 원격 근무 자격 조건이지 한국 소재 기업/사무실 공고를 뜻하지 않는다. 각 공고의 `locationRestrictions`, `timezoneRestrictions`, `expiryDate`를 추가 확인해야 한다. 공식 문서는 사이트 내 사용 시 출처와 원문 링크 표시를 요구한다. |
| [Remotive](https://github.com/remotive-com/remote-jobs-api) | HTTP 200, 17건. 위치 제한에 `Worldwide`가 명시된 건 5건, `Korea` 명시는 0건. | 원격 공고 전용이다. 공식 문서는 출처·원문 링크 표시, 하루 최대 4회 권장, 구인 목록을 보여주기 위한 가입 강제 금지를 안내한다. [이용 안내](https://remotive.com/remote-jobs/api) |
| [Remote OK](https://remoteok.com/faq) | HTTP 200, 공고 객체 99건. 위치에 `Korea` 명시 1건, 위치 공란 31건. | 위치 공란을 한국 지원 가능으로 취급하면 안 된다. 공식 FAQ는 공개 JSON 피드 재사용 시 출처와 원문 링크 표시를 요구한다. |

이 세 피드는 국내 다직군 공고 공급원의 대체재가 아니라 **원격 채용 보조 공급원**이다. 반환 건수는 특정 시점·요청 한 번의 결과이며 전체 시장 규모나 실제 지원 가능 공고 수로 해석하지 않는다. 특히 Remotive의 위치 명시 5건과 Remote OK의 위치 공란 31건을 모두 추천 대상으로 세지 않는다.
