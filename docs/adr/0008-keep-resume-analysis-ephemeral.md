# Keep resume analysis ephemeral

JobLens does not retain a Candidate's full Sanitized Resume for future visits or persist deep Analysis Results for later retrieval. The Candidate-approved Sanitized Resume may remain in the current browser tab's memory for sequential recommendation batches and selected deep analyses, but refresh, tab close, sign-out, or explicit clearing ends that reuse and requires another Extraction Review. The Next.js BFF receives approved text in request memory to enforce identity, Daily Analysis Allowance, and the paid-analysis kill switch before invoking Bedrock; it does not place the content in databases, files, caches, queues, logs, analytics, or error reports. References are released immediately after success, failure, or cancellation, and an invocation plus any unexpectedly surviving temporary processing state expires no later than 15 minutes after request start. Evidence-insufficient results remain session-only. Recommendation History is an explicit, narrower exception: when source retention permission allows it, history persists actual recommendation reasons with paired verified Job Posting and approved Resume excerpts as described in ADR-0011, and therefore remains sensitive Candidate data.

The browser coordinates per-listing requests, so analysis cannot resume after refresh or tab close. Client cancellation triggers a best-effort server cancellation and discards later output, but an already-started model invocation can still consume allowance and cost. Each new Resume Version requires a preview and explicit analysis action; subsequent requests for that version retain a visible transfer notice without repeating consent.
